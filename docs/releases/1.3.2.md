# Harbor 1.3.2

- Keep chatting and pasting text while a file is waiting for acceptance or transferring.
- Choose and submit additional files and images without waiting for the active transfer. Harbor queues up to 16 extra attachments and sends them in order within each conversation.
- Send ordinary files directly from the native chooser, without an extra Send step.
- Show the queued count; Cancel sends cancels the active send and clears that conversation's queue.

Recipient acceptance and helper transport/security checks remain in place. The queue is held in memory, not persisted across shell reloads. This patch changes the QML interface, not the helper protocol or private data formats.

The release also contains the previously committed Harbor interface and device-link work already on main; the larger Harbor 2 roadmap remains incomplete. See docs/stages/harbor2.md for its acceptance scope.

Validation: the full headless `make test-ci` suite, QML lint, architecture checks, manifest validation and diff checks passed. Native composer/input fixtures also passed, including the composer with an active file-transfer projection. The uninstall mount-boundary subcheck was unavailable; complete queued multi-file relay E2E remains unverified. Details are recorded in docs/stages/harbor2.md.
