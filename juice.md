# Harbor creative compass

Read this core before experience changes; read only relevant future linked
entries. Preserve useful discoveries and remove stale guidance as work changes.
[Specification](docs/SPECIFICATION.md) owns protected requirements;

## A familiar place
Owner-approved direction (23 October 2026): quiet, compact, keyboard-first,
following the active Omarchy theme; polish the existing native interface.
Interpretation: Harbor should feel already at home on the machine. Use existing
shell tokens, spacing and controls. Let conversation content carry the color;
avoid decorative nautical scenery, new palettes or attention-seeking motion.
Check the result under different Omarchy themes and narrow windows.

## Continuity you can see
Interpretation of linked machines and history sync: relief comes from seeing
where things stand. Possible realization: one restrained sync line that changes
from catching up to current, with actionable missing-history or offline states.
Keep repeated success quiet; reserve emphasis for a new device requiring consent.
This is a creative possibility, not an approved layout or implemented behavior.

## Trust through clear moments
Interpretation of explicit linking and dated recovery: make consequential steps
legible. Device name, matching verification code and the backup's date deserve
space. State the scope before confirmation; give a clear completion or recovery
action afterward. Do not turn normal chatting into a security dashboard.
Verify by walking through linking, rejection, revocation and failed restore.

Tyler approved the redesign map and Harbor rebrand on 24 October 2026, then
authorized complete implementation. `docs/REDESIGN.md` now owns the target
experience; retain native shell tokens and verify each implemented journey.

## Everyday actions first

Tyler’s direction, 24 October 2026: reduce friction throughout Harbor. Incoming
messages and file requests should visibly open the relevant chat and play sound,
subject to explicit popup/mute preferences. Incoming invitations must be visible.
The paperclip opens a chooser directly; paths and security maintenance are not
the normal conversation workflow. Remove promotional GitHub/Ko-fi controls.
Present people and their conversations first, with identity/device management
under settings. Keep consequential trust and deletion decisions clear without
adding repeated confirmations to ordinary actions.
